Give **only** the short, plain explanation. Nothing else.

Subject: if `$ARGUMENTS` is non-empty, explain that. Otherwise explain **the last substantive
thing you said** in this conversation — the previous answer, plan, or summary.

Rules:

- A few short sentences, or 3–5 bullets. Whichever is clearer. Hard stop at that size.
- Everyday words only. No jargon, no acronyms, no code identifiers, no file paths, no
  metric names. If a term is truly unavoidable, say what it means in the same sentence.
- One idea per sentence. Say the concrete thing, not the abstract category.
- An analogy is welcome if it genuinely lands. Don't force one.
- **Keep the facts exact.** Simpler wording, same truth — never blur a number, a name, or
  a conclusion to make it read smoother. If something really is uncertain, say "not sure
  yet" in those words.
- No preamble ("Sure! Here's the simple version"), no caveats section, no tradeoffs, no
  next steps, no tail checklist, no offer to go deeper.
- Don't re-run tools, don't re-read files, don't redo the analysis. This is a rewording of
  what you already know. The only exception: if `$ARGUMENTS` names something you have not
  actually looked at yet, look it up first, then explain it plainly.
- Do not apologise for the earlier version or comment on how it was too complicated. Just
  give the plain one.
