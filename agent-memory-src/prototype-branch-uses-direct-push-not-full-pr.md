The default way to land a fix or add work on `lane/mechanical-dispatcher` (epic #3383's prototype branch) is the sanctioned POC fast-lander, `scripts/operations/poc-land.mjs` (transport A′, ratified by backlog #3637's "POC-branch delivery mode" decision) — not the full PR+review+CI+drain pipeline `main` uses, and not a bare hand-run `git push` either (that shape, option A, was considered and rejected: it races concurrent writers and collides with the live branch-sync loop). The whole point of a prototype branch is to move fast; routing prototype-only work through the same heavyweight pipeline as `main` defeats that purpose, and concretely fails today anyway, since this base branch has no CI wired to it at all (a separate, real, already-filed bug: backlog 3674) — a PR against it can never get a green check and get stuck in the drain forever.

Why: surfaced 2026-09-14 during epic #3383's incident-response chain. One fix that night (the stale-main-ref bug, commit 14e0a7249) correctly used the direct-push path and landed cleanly. A second fix the same night (PR #2236, the verify-dispatch timeout bug) instead went through the full PR pipeline and got stuck exactly as predicted — needing an explicit operator break-glass decision to resolve, purely because of process choice, not because anything was actually wrong with the code (it had already passed real tests, check:standards, and an independent 5-lens review with zero findings before getting stuck).

How to apply:
- **Test before landing, every time, no exceptions:** `poc-land.mjs` skips PR/review/CI *ceremony*, never skips *verification* — it gates the push on the item's own tests/build (`scripts/verify-lane.mjs`) itself, but treat that as a floor, not a substitute for doing it properly. Run real tests, `check:standards`, and the sanctioned verify-lane gate locally — with the same rigor a PR would demand — before invoking it. This is a shortcut around process overhead, not a shortcut around proof the change works.
- Before dispatching or building a fix/feature that targets `lane/mechanical-dispatcher` only (not code that also independently lives on `main`), default to landing it with `poc-land.mjs` as described above — verify locally as above, then run the lander, no PR needed.
- Reserve the full PR pipeline for work that also needs to land on `main` (where CI genuinely runs and review has real teeth) — don't default to it out of habit for prototype-only work.
- If a fix already went through the wrong path and got stuck on the CI-gap bug (3674), the fix is to switch it to the `poc-land.mjs` path at that point, not to force it through the stuck pipeline with a break-glass override — the override should stay reserved for cases where the direct-land path itself isn't available or appropriate.
- This doesn't change how `main`-targeting work should be handled — that still goes through the full pipeline, since CI and review genuinely function there.
