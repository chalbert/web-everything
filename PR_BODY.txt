Make prepare use Codex and centralize operation routing policy

Card-only prepare currently returns to Claude after old probation failures, and changing a model requires finding several independent defaults. Add we:scripts/lib/dispatch-routing-policy.json as the operator-editable policy. Prepare now selects Codex/gpt-6-astra, with Claude/claude-sonnet-5-5 as its declared fallback. Other operations inherit today's evidence, tier and probation decisions until given an explicit route.

The policy header includes an edit example. Entries support operation names, task types, judge:<operation>, and review-seat:<lens>. Aliases are provider-specific and resolve to explicit IDs. Unknown providers, model IDs, aliases, keys and malformed entries are rejected with their location. The shared reader retains its last valid immutable snapshot through bad edits, logs the reason, and forwards that snapshot to detached children. The source loader reads an inherited snapshot before touching a potentially broken file.

Build/fix/ci-heal retain the critical-work gate. Its gated kinds and open task-type rows now live in the same policy. Explicit policy cannot bypass a closed gate or a recorded critical-miss veto. Review call grouping includes model and effort, so two seats selecting different models on the same provider receive separate, budget-reserved calls.

How to use

In we:scripts/lib/dispatch-routing-policy.json, replace an operation's inherit entry with, for example:
  "build": { "provider": "codex", "model": "gpt-6-sol", "fallback": [{ "provider": "claude", "model": "sonnet" }] }
The critical-work gate still applies. Removing a kind from criticalWorkGate.kinds is an explicit operator change to that gate. Model-only/native routes can use the Claude aliases; judge:review-pr changes that operation's judges; review-seat:claim-accuracy changes that added seat. Provider changes use existing adapters: native-agent-only paths select the declared Claude fallback, and missing mechanical wrappers are unavailable rather than silently pretending to launch the requested provider. This change does not implement the absent fix/prepare mechanical wrappers.

Fallbacks are selected before launch when an adapter/CLI is unavailable (or when the critical-work gate excludes the primary). An indeterminate launch is never automatically retried, avoiding two concurrent writers. Existing per-item holds and completion/stamping checks remain in force. An explicit prepare policy supersedes the old global historical-failure circuit breaker; inherit restores that historical routing behavior.
