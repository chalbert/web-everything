# Review and fix dispatch should get the same minimal-context wrapper treatment build dispatch got (downstream of #3627)

NOT YET DECIDED — research/proposal item, matching the record-do-not-ratify posture we:backlog/3627 and we:backlog/3628 already use. Follows directly from #3627s live-tested minimal-context delivery wrapper (design PR #2107, we:scripts/operations/deliver-item-wrapper.mjs, proven end-to-end tonight 2026-09-09 against real item #3371) — this is the design pass for the SECOND dispatch kind to graduate, per we:docs/agent/prototype-based-dev.md (read in full before filing; its park-until-genuinely-exercised, driver+observer live-test, checklist scorecard and graduation-gate discipline is the bar this eventual build is held to, explicitly cited here so it is not silently skipped). Read we:scripts/operations/review-dispatch.mjs in full before filing: it spawns a reviewer/fixer through we:scripts/operations/dispatch-lane-io.mjs buildAgentArgv/defaultSpawnAgent, the SAME unstripped claude --bg mechanism build dispatch used pre-#3627 — every dispatched reviewer inherits the operators personal home we:CLAUDE.md, this repos own we:CLAUDE.md to we:AGENTS.md to docs/agent doctrine chain, and full skill auto-discovery, none of which it needs. Also read we:skills-src/review/review-agent-brief.md and we:skills-src/conveyor/fix-agent-brief.md in full (the REAL current briefs, not guessed): a dispatched REVIEWER session today does almost nothing but shell CLIs — report started (we:scripts/operations/completion-cli.mjs), acquire a lane (we:scripts/lane-pool.mjs, --wait-ms), run we:scripts/operations/review-loop-cli.mjs exactly once (which itself spawns two independent jurors via we:scripts/lib/judge-spawn.mjs under --safe-mode, already isolated and tool-free per #3370s own lowest-risk-boundary framing), read that CLIs own structured verdict VERBATIM (never re-interpret it), report done, release the lane, exit. No file is ever edited. No judgment is performed inside the dispatched session itself — the actual judging already happens inside we:scripts/operations/review-loop-cli.mjs own sub-spawned jurors, and the review brief explicitly forbids the dispatched session from improvising or re-deciding anything. A dispatched FIXER (we:skills-src/conveyor/fix-agent-brief.md) is a genuinely different shape: reconstitute a bounced PRs work in a lane from its existing ref, read the reviewers finding via gh pr view, apply a REAL code fix (actual judgment, editing files, the fixers whole point), run the locus gate, spawn ONE adversarial code-review subagent on its OWN diff before pushing (brief step 5 — the identical self-review-inside-the-agents-own-turn anti-pattern #3627 already flagged and moved out of the BUILD agents old step 6), commit, push HEAD to the SAME existing lane ref, rearm review via we:scripts/conveyor/rearm-review.mjs, drop a learning, exit — never merging or self-clearing review:human, same as review.

Concrete design call, reasoned rather than left open (per this items own instructions): TWO separate wrapper mechanisms, not one wrapper with two brief variants, because the two kinds differ at the one point that matters for a minimal-context redesign: whether the dispatched process needs an LLM turn AT ALL. (1) REVIEW: propose a we:scripts/operations/review-dispatch-wrapper.mjs that is PURELY MECHANICAL, spawning no Claude agent for the top-level orchestration at all — we:scripts/operations/review-loop-cli.mjs already prints a structured JSON verdict and already runs its own independent jurors, and we:scripts/lib/review-independence.mjs self-clear refusal keys on the CLAUDE_CODE_SESSION_ID env var, which any process (not only a live Claude session) can set to a fresh random UUID before shelling we:scripts/operations/review-loop-cli.mjs directly — the exact same acquire-lane, shell-one-CLI, release-lane shape we:scripts/operations/deliver-item-wrapper.mjs already uses for its own mechanical steps (acquireLane, runVerifyOperation), just with zero LLM turn anywhere in the critical path. This is a genuinely stronger move than shrinking context — it deletes an unnecessary Claude spawn from the review path outright. Flagged as the single biggest claim needing empirical verification (matching we:scripts/operations/deliver-item-wrapper.mjs own discipline of never asserting a CLI-flag interaction without running it for real) before any build starts: is there truly nothing besides the identity check that requires a live Claude session here? The reviewer briefs own "if we:scripts/operations/review-loop-cli.mjs reports something this arc does not cover, stop and report structured outcome, never improvise" clause suggests no live judgment is actually wanted in that seat, which is exactly the kind of case-not-covered handling a wrappers own deterministic branching (like we:scripts/operations/deliver-item-wrapper.mjs decideParkMode) already does in plain JS for build. (2) FIX: mirror we:scripts/operations/deliver-item-wrapper.mjs own proven shape directly — reuse its CLAUDE_RESTRICTED_PROVIDER (the verified --restricted plus explicit --tools allowlist plus --strict-mcp-config plus --disable-slash-commands plus a trimmed --settings hooks file combination, chosen there specifically because --safe-mode was empirically proven to silently drop hook enforcement for a TOOL-BEARING spawn) for a genuinely minimal we:skills-src/conveyor/fix-agent-brief-v2.md, because a fixer performs real code-editing judgment the same way a builder does. Concretely narrower than the build brief: no lane-pool/conveyor vocabulary (wrapper reconstitutes the PR ref and hands the agent a live cwd, the SAME true-push-never-poll pattern deliverItem already proves), no PR/label/rearm mechanics in the agents own turn (the wrapper drives gate plus ONE converge pass on the fix itself, mirroring deliverItem step 4, replacing the agent-initiated adversarial subagent the current brief step 5 has it spawn on its own diff), and a small closed outcome contract mirroring the delivery reports outcome enum plus the existing we:scripts/conveyor/stand-down.mjs reason vocabulary (fixed / blocked / escalated-needs-judgment / escalated-conflict) instead of the agent itself shelling gh pr view, we:scripts/conveyor/stand-down.mjs and we:scripts/conveyor/rearm-review.mjs. The wrappers own mechanical layer would call we:scripts/conveyor/rearm-review.mjs / we:scripts/conveyor/stand-down.mjs based on the agents reported outcome, the same shift-orchestration-out-of-the-agents-turn move #3627 already made for build gate/converge/PR/escalation.

Open calls flagged explicitly for the operator rather than decided silently, per this items own instructions: (a) whether the review wrapper genuinely needs zero LLM turn is a design claim here, not yet independently verified against the real we:scripts/lib/review-independence.mjs refusal path and we:scripts/operations/review-loop-cli.mjs own output contract the way #3627s CLI-flag claims were each re-run against the real binary before being asserted — recommend an explicit smoke-test step before committing to "no agent at all" as final. (b) whether moving the fix agents step-5 self-review out of its own turn (mirroring build) is right for fix specifically, given fix diffs are typically much smaller than a full build and standing up a wrapper-driven panel/red-team for a one-line repair may be disproportionate cost versus letting a small fix keep its own lightweight subagent self-check — I judged move-it-to-the-wrapper for consistency and because the SAME self-review-conflict-of-interest objection applies regardless of diff size, but this is a real tradeoff, not an obviously free win. (c) file layout: whether fixs wrapper should be a new fixItem function inside we:scripts/operations/deliver-item-wrapper.mjs itself (reusing acquireLane/resolveLanePath/runVerifyOperation/runConverge/CLAUDE_RESTRICTED_PROVIDER verbatim, since the shape overlaps heavily) versus a separate file importing those as shared primitives — leaning toward extending the same file for fix (high primitive overlap) and a wholly separate, much smaller wrapper for review (almost no primitive overlap once no agent is spawned) but recorded as a lean, not a ruling. (d) this design directly informs we:backlog/3628-generalize-mechanical-lane-acquisition-to-every-dispatched-a.md own still-open question ("whether the same foreground-blocking trick even applies to a backgrounded, fire-and-forget review dispatch") — if the review wrapper needs no agent turn at all the question dissolves for review specifically, since there is no backgrounded spawn left to make foreground; it remains fully open for fix, which does need a real agent turn and should adopt the same never-bg, foreground-blocking pattern #3627 already proved for build, not a fresh design.

## Ruling (2026-09-09, operator) — three of the open calls above are now DECIDED; the item as a whole stays open

The operator ruled on three of the calls this card flagged as open, in a follow-up session that also verified open call (a) from source and built the reviewer side. Recorded here as a ratification of those three specific calls, not a resolution of the whole item — the fixer mechanism (see below) is still unbuilt and neither mechanism has had its we:docs/agent/prototype-based-dev.md live exercise yet, so `status: open` stays unchanged, matching we:backlog/3627's own posture (ratified design, still-open card, while the build/exercise continues).

1. **TWO separate primitives, sharing a common module — settles open call (c), OVERRIDING this card's own "leaning".** Never one monolithic file, never literal duplication. This card's own body (above) leaned toward extending we:scripts/operations/deliver-item-wrapper.mjs directly for fix and a wholly separate file for review; the operator ruled a THIRD shape instead — a shared module both import. Built as we:scripts/operations/minimal-context-provider.mjs: the verified `CLAUDE_RESTRICTED_PROVIDER` argv shape (`buildRestrictedProviderArgv`), hooks-settings generation (`createHooksSettingsWriter`, a factory — the delivery wrapper's own `ensureDeliveryHooksSettingsFile` is now literally `createHooksSettingsWriter('we:delivery-agent-hooks-settings.json', DELIVERY_HOOKS_SETTINGS)`, not a re-derived copy), lane acquire/release (`acquireLane` — now supports BOTH the original numbered-lane shape build uses and an unnumbered shape matching we:skills-src/review/review-agent-brief.md step 1's own real acquire; `releaseLane`/`releaseAllPools`), and the gate-running pattern (`runVerifyOperation`). we:scripts/operations/deliver-item-wrapper.mjs now imports these instead of defining them locally — an EXTRACTION, not a rewrite; its own pre-existing 106 tests pass unchanged (verified: `npx vitest run we:scripts/operations/__tests__/deliver-item-wrapper.test.mjs` — 106/106 green, byte-identical behaviour).
2. **A fixer's self-review moves OUT of its own dispatched turn — settles open call (b) as a definite ruling, not a tradeoff.** Same ruling as build (we:backlog/3627): independence is structural (the self-review-conflict-of-interest objection applies regardless of diff size), never proportional to how small the diff is. The fixer mechanism itself is explicitly OUT of scope for this build pass (see below) — this ruling applies once it is built.
3. **Build and prove the REVIEWER mechanism first, one at a time.** The fixer mechanism is explicitly OUT OF SCOPE for this pass — not designed further here, not built. Built: we:scripts/operations/review-dispatch-wrapper.mjs, a PURELY MECHANICAL wrapper (no `DeliveryAgentProvider`-shaped Claude spawn anywhere in its critical path) — acquire a lane (`--purpose=review-loop`, matching the real brief's own `--wait-ms=30000` self-healing acquire), mint a fresh `CLAUDE_CODE_SESSION_ID` for independence, run we:scripts/operations/review-loop-cli.mjs exactly once with `--json`, classify its structured output (`classifyReviewLoopOutcome`, PURE) into the same `bounced`/`auto-cleared`/`parked` vocabulary we:skills-src/review/review-agent-brief.md step 3 already uses, report through we:scripts/operations/completion-cli.mjs (the SAME `#3436` durable-trace mechanism the real dispatched-agent brief already uses), release the lane.
