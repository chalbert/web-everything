## What is already ruled (not re-asked here)

- **How a slice is ported.** Any time, whatever the sync state; as a diff onto `main`'s current file, never a copy; a file in the open conflict set takes the staging ref's version (ruled 2026-09-21, #3804 Fork 4, codified in `we:docs/agent/platform-decisions.md#poc-branch-mechanical-sync` clause 4). It also means the health chain no longer gates slices. Everything below composes with that rule and none reopens it.
- **Each increment is its own small pull request, never a bulk merge** (#3443 Done-when 3, the epic's own rule).
- **A PR closed unmerged is terminal** in the reaper's repo-less check; only an OPEN PR blocks (operator, 2026-09-20). It stays, pinned by a test.
- **The stop-verify design** (one registry re-read after a 5 second wait, confirmed, unconfirmed and already-terminal counted apart, terminal sessions never re-stopped) is built and tested on the prototype (`e0165b4e9`; `we:scripts/conveyor/session-reap-stop.mjs:122` holds `STOP_CONFIRM_WAIT_MS = 5000`). ## Ratify — the reaper graduates in slices, planner first, facade swap last (the filed draft's Fork 1)

*Why this is not a fork:* graduating is forced, and how to cut the increments is packaging that #3443 Done-when 3 and `#poc-branch-mechanical-sync` clause 4 already settle. The one broken branch is to keep the reaper on the prototype: when the dispatcher runs from `main` (`#poc-branch-declared-delivery-mode` clause 4(a): the runner's steady state tracks `main`), `main` would carry the reaper that re-stops about 570 finished sessions per run and has no verdict axis, and #3443 Done-when 1 accepts leaving a commit behind only with a named reason, which none holds here. Writing the whole reaper as one piece is not broken, only larger (9 new files, about 2.2k lines, 1,035 of them the watchdog chain, plus a rewrite of the live entry point, in one diff); slicing does not make S5 easier to revert, it makes S1 to S4 read as additions with tests so that review goes to the one slice that changes what `main` does.

**To ratify:** the slices below, in this order, with #3744 closing at S5 and S6 held for #3684.

S2, S3 and S4 are independent once S1 is in and can land in any order; S5 needs S1 to S4. S1 waits for nothing on the prototype: it is inert on `main`, so a known crash in it (#3765) or a third `normalizeHandle` copy (#3766) reaches no run. The port source for a file in the conflict set is the staging ref's version (see FOUND). **Honest cost:** S1 to S4 are dead code on `main` until S5, five pull requests instead of one, and #3744 stays open until S5.

Known occurrences of the pattern: Fowler's Strangler Fig ("Since these components are small, there isn't so much risk involved when we introduce the new software"), Branch By Abstraction (the facade is the abstraction, the split modules are the new supplier; the system "builds and runs correctly at all times"), Parallel Change (land the new beside the old, then switch), and Google's engineering practices (100 lines reasonable, 1000 usually too large). In this repo, #3443's landed slices (#3481, #3484, #3483, where the supervisor was ported byte-identical with its 64 tests) and the inert-first landing of the review-tag modules. A hybrid, fixing #3744 directly on `main` in the monolith or by wiring the stop module into it early, is rejected: `main` gets a shape neither side has, the fix is written twice, and the next sync merge conflicts on `we:scripts/conveyor/session-reaper.mjs` until the split graduates anyway.

**Skeptic:** SURVIVES-WITH-AMENDMENT. The attack found S5 is where four unreviewed behaviours go live (so the "cannot revert apart" argument against one piece was symmetric and is dropped in favour of review size), a human gate answered inside S4 (now Fork 1), that S1 need not wait on #3765 (now S5 is the gate), and that the keep-on-prototype rejection leaned on a clause that authorizes one-unit graduation (now cites clause 4(a) and #3443 Done-when 1). Slicing beat every attempt to prefer one piece, keep-on-prototype or the hybrid.
**Screen:** flagged(impl|prio) → dissolved from a fork to this ratify block: the fresh screen found that slice order is packaging the epic already rules, and that with both branches free to build the end state is identical.

## Fork 1 — does the unattended stuck-session clear graduate with the stop module

*Fork-existence:* on `main` the reaper either clears a stuck session with no human step or leaves the human step in place, and the two cannot both hold. The excluded branch is graduating it as the prototype built it: that rules #3684, an open decision the operator has directed to be data-first, inside a code review.

There is a real argument the other way, and it is #3684's to weigh, not this card's. The prototype's header says the reaper already stops a `done` or `failed` session with no human step, and a `blocked` or `working` one on a single fact, so the stricter five-fact `assessStuck` gate does not need a person (`we:scripts/conveyor/session-reap-stop.mjs:23-47`); and `#human-required-is-judgment-only` (`we:docs/agent/platform-decisions.md`, line 3914) reserves a person for judgment, not for reading a deterministic verdict. Against it: the operation's own header reserves this confirm for a person; the in-repo pattern for graduating a gate is a scorecard of real outcomes feeding a bar (`we:scripts/conveyor/run-scorecards.json`, `#model-probation-graduation-criteria`, #3654), which #3684's approved direction reuses, and there is no such record for this clear (0 unattended runs, 13 human ones); and the same split exists outside the repo, where Terraform's `apply` asks for approval by default and `-auto-approve` is an explicit opt-in the docs advise using only after a reviewed plan. The repair fires only when `claude stop` throws, not for the 28 sessions whose stop "succeeded" but still list (#3744), so holding it back costs little.

- **(a) [default] Split the repair out; graduate the rest.** On the prototype the repair moves to its own module (`we:scripts/conveyor/session-reap-clear-stuck.mjs`), so S4 and S5 carry neither `clearStuckSessionAutoConfirm` nor `attemptClearStuckSession`. In the stop module that is a clean tail cut (imports `we:scripts/conveyor/session-reap-stop.mjs:56-65`, functions `:229-314`, header `:23-47`). In the facade it is about seven hunks (`we:scripts/conveyor/session-reaper.mjs` at the import `:66`, the re-export `:90-96`, the `--no-clear-stuck` flag `:130`, the repair block `:250-267`, the `cleared` counter and its two output sites `:283`, `:299`), and two tests pin it (`we:scripts/conveyor/__tests__/session-reaper.test.mjs:26`, `we:scripts/conveyor/__tests__/session-reap-stop-cli.test.mjs:121-265`); the `main` port omits them. On `main` a failed `claude stop` is logged as it is today. **The prototype is untouched:** its runner keeps clearing unattended, because landing inside a POC branch skips review by design (`#poc-branch-declared-delivery-mode` clause 2), so the split decides only what graduates. S6 (the repair) is `blockedBy` #3684, which still needs `/prepare` and whose scorecard has no card; the prototype also widened the operation from `blocked` to `blocked` plus `working` (2026-09-14) while #3684 asks about one exact signature, so S6 or #3684 carries that widening. The facade then differs from the branch's by those hunks until S6, the same superset relation every graduated slice has.
- **(b) Graduate it as built; the graduation review decides.** Rejected: the graduation review (`#poc-branch-declared-delivery-mode` clause 3, `review:human` for gate machinery) is where a person would meet it, but that review would be ruling an open decision with no scorecard, and #3684's direction was to collect the data first.
- **(c) Graduate it opt-in and off by default, on both `main` and the prototype.** The strongest alternative: identical code on both sides and no split, like Terraform's `-auto-approve`. Rejected as the default: it ships the unattended path to `main`, where flipping the default is a one-line edit that is the #3684 ruling without its data, and it changes the prototype's live behaviour (its runner passes no flags) with nobody having asked. If the operator would rather have no divergence, this is the fallback, and the ruling then reads "the unattended clear is opt-in everywhere until #3684".

**Skeptic:** SURVIVES-WITH-AMENDMENT. The attack found the facade differs by about seven hunks, not one line, and the stop module has no injected hook (both corrected above); that the clear is recoverable by hand, not "unrecoverable" (the wording now quotes the operation's own header); that the prototype's runner clears unattended, so the "no track record" argument binds only `main` (now stated, and why it is by design); that `#human-required-is-judgment-only` cuts toward automation (now named as the argument for (b)); and that opt-in on both sides is a stronger (c) (now the named fallback). The default survived because the question is already an open, operator-owned decision with a data-first direction, and code review is the wrong place to close it.
**Screen:** clear. (The screen ran before the skeptic's corrections; they changed evidence, not the framing.)

## Fork 2 — what an untagged PR session name means on `main` (was Fork B in #3443)

*Fork-existence:* one name string has one meaning to the reaper. `review-148` is either WE#148 or an older plateau-app#148, and no single rule is right for both. Rule (b) reaps a live session whose real PR is open in another repo; that is the excluded branch.

- **(a) [default] Keep the every-repo check for every untagged name, with a sunset pinned by a test** (the filed default). It errs on the safe side: only when every existing PR of that number is terminal does it reap, and then the session's real PR is terminal whichever repo it was in (see FOUND for the one edge and the cost). "Until legacy names age out" has no end today because the prototype's runner and four staging-ref minters still emit untagged names for other repos, so the sunset is stated as a code condition, not a fleet state: delete the every-repo branch when both hold, (i) no minter can emit an untagged name for a non-WE PR, pinned by a contract test that drives every minter (the five listed in FOUND) with a non-WE repo, and the runner runs that code; and (ii) no non-terminal untagged PR-style session in `claude agents --json --all` is older than the day (i) was running, after stuck rows past an age cutoff are stopped by hand (they are not evidence either way). Today neither holds. A card carries the deletion (carved at resolve). Until then, on `main` the order collapses to tag, then every repo, because the ledger does little there (Supported by default, `readFollowUps`).
- **(b) Trust WE for every untagged name.** Rejected: wrong for the names the prototype's runner and the staging-ref minters produce today for other repos, and for the legacy names the operator's own example shows (`review-148` was plateau-app#148). The reaper stops a running session, so the error is not free.
- **(c) Key on the session's own `startedAt` against a marker cutover.** Rejected: it is pure (the planner already receives `startedAt` per row, `we:scripts/conveyor/session-verdicts.mjs:98`, and a compare against a constant reads no clock), but the cutover is not a fixed moment. The commit landed 08:45 EDT, the first tagged session started 12:17 EDT, and the prototype's runner and four minters still emit untagged names for other repos, per minter and per machine. A value taken from any one of those treats a live other-repo session as WE. Once the sunset holds, (c) is unnecessary because the branch it would gate is deleted.

**Skeptic:** REFUTED as first written (default (c)) → flipped back to (a). The attack: the prototype's live minter still writes untagged `review-<N>` for other repos, so "untagged after the cutover means WE" would treat a live plateau-app or frontierui review as WE#N, find WE#N terminal, and stop it. A second pass then found the first draft of (a)'s sunset was itself false (four staging-ref minters are still untagged, and a fleet-state condition blind to names minted after the restart can never fire on stuck rows) and that "collisions are rare" was backwards (they exist; the check is safe because an open PR anywhere keeps the session). All folded in above; (a) with a test-pinned sunset survives.
**Screen:** clear.
