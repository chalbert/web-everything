# Gate Workflow harness launchability in check:standards (the meta pure-literal rule)

Carved out of PR #1037 by operator ruling after five review rounds in which ALL TEN findings landed in this guard and ZERO landed in the one-line fix it was riding. The fix (collapsing a concatenated meta.description) shipped alone; this is the prevention. WHY IT IS OWED: the Workflow runtime requires 'export const meta' to be a pure literal and rejects the script before any agent spawns, so an impure meta makes a harness UNLAUNCHABLE and the failure is silent — it never runs, so it never produces a wrong answer. we:scripts/workflows/review-parked-prs.mjs was unlaunchable from the day it was written and three layers above it inherited the silence for weeks. The class already recurred once (#2664, resolved with no gate), which under the capture rule makes a class-level guard owed. WORKING IMPLEMENTATION EXISTS on lane/converge-loop-launchable-only at commit 0433216c — an I/O-free core at we:scripts/lib/workflow-meta.mjs, 31 tests, and check:standards rule 16, with all three gate arms verified firing on real files. Recover it from there rather than rewriting. THE FINDINGS IT MUST KEEP, each of which cost a review round: (1) reject by AST node KIND, never by regex — the regex draft passed a-plus-SUFFIX concatenation, buildPhases() and mixed-quote concatenation while false-flagging a prose ellipsis; (2) a COMPUTED key is a name syntactically and an arbitrary expression semantically, so exempting names wholesale let a computed key read as pure; (3) resolve the aliased export form through propertyName, not the exported name — looking up by name found an unrelated pure local and returned an affirmative ok:true on an unlaunchable harness, which is worse than a skip; (4) an export spelling that cannot be resolved (export default, export let + late assign, re-export) is a harness FAILED TO READ, not a non-harness — it must ERROR, never continue; (5) select files by parse, not by a text match on the export line, which skipped the declare-then-export spelling entirely; (6) assert the sweep is non-empty, or renaming a root leaves the gate green forever over zero files; (7) the walk must gate on isFile() and wrap its fs calls — a symlinked directory named like a script throws EISDIR and aborts the whole health gate before its other rules run. AND THE HONEST CAVEAT, which must survive into whatever ships: PURE_KINDS MODELS an external validator this repo cannot import. Only two rejections are observed (both BinaryExpression — #2664's recorded error and we:scripts/workflows/review-parked-prs.mjs); everything else is inference from the error wording. The failure directions are asymmetric — too strict is a loud false alarm, too loose means the check passes and the harness still cannot start — so when in doubt leave a kind OUT. There is NO PreToolUse hook for this (verified against we:.claude/settings.json), so do not claim author-time enforcement. The only real integration proof is a launch.
