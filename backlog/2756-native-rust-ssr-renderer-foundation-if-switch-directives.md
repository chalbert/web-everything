# Native Rust SSR renderer foundation + if/switch directives

Stand up the greenfield Rust build subtree (frontierui:plugs/webdirectives/ssr/rust/) for the native SSR renderer: source parse (html5ever/scraper, the Servo HTML5 parser, mirroring the Node happy-dom strategy — the parser choice is a conforming black box per #2030, not a fork) + top-level template-is dispatch loop + normative space-padded marker wrapping + renderMarkerOptions + shared helpers (resolve_path, mustache interpolate), plus the Rust-side cross-language conformance harness runner that reads we:conformance-vectors/webdirectives-ssr.vectors.json and byte-compares per the #2354 contract, wired into cargo test + repo CI.

Includes if + switch (share interpolate innerHtml, resume tokens ride generic renderMarkerOptions) to prove the pipeline end-to-end. Demo: passes if, switch, state-tokens vectors byte-for-byte. Mirrors the Node reference oracle at frontierui:plugs/webdirectives/ssr/nodeReferenceRenderer.ts. Fork-free build (#2030 black box). The foundational slice B/C ride on.

## Design

**WE side is already built and is the only half this repo can pin.** The corpus is
[we:conformance-vectors/webdirectives-ssr.vectors.json](conformance-vectors/webdirectives-ssr.vectors.json)
— a committed projection of `we:conformance-vectors/webdirectives-ssr.vectors.ts`, regenerated by
`npm run gen:webdirectives-ssr-vectors` and drift-tested in CI — and the grading protocol is
[we:conformance-vectors/webdirectives-ssr-harness-contract.md](conformance-vectors/webdirectives-ssr-harness-contract.md).
Everything this item builds is a **consumer** of those two files; nothing in WE changes.

**The corpus, exactly as it stands (10 vectors).** The harness must load and grade all of them; this slice's
DEMO bar is the five marked ✔ below (`if`, `switch`, and the two `state-tokens` cases, plus the `for-each`
state-token case only if `for-each` lands here — otherwise it is slice B's):

| vector id | in this slice |
| --- | --- |
| `webdirectives-ssr/if/true-branch-emitted` | ✔ |
| `webdirectives-ssr/if/false-branch-empty-markers` | ✔ |
| `webdirectives-ssr/switch/active-case-only` | ✔ |
| `webdirectives-ssr/state-tokens/if-condition-resume-token` | ✔ |
| `webdirectives-ssr/state-tokens/switch-value-resume-token` | ✔ |
| `webdirectives-ssr/for-each/keyed-items-expanded` | slice B |
| `webdirectives-ssr/for-each/empty-list-markers-only` | slice B |
| `webdirectives-ssr/for-each/state-tokens-three-items` | slice B |
| `webdirectives-ssr/resource-loader/resolved-data-inline` | slice C |
| `webdirectives-ssr/defer/placeholder-branch-emitted` | slice C |

**The grading protocol is fixed by contract, not by the harness author's taste** — the five rules in
`we:conformance-vectors/webdirectives-ssr-harness-contract.md` §*The grading protocol* are normative: strict
byte/codepoint equality (no DOM diff, no whitespace insensitivity), UTF-8 decode on both sides with no
normalization, every vector independent, and **all** failing ids reported, not just the first. A conformant
run is `{ passed: string[], failed: { id, got, want }[] }` with `failed` empty.

**Two portability traps a Rust port specifically hits:**

- **`key-hash` is DJB2 over UTF-16 code units, not UTF-8 bytes.** Rust's `str` iterates `char` (Unicode scalar
  values) and its bytes are UTF-8, so the natural Rust spelling is wrong in both directions. Use
  `str::encode_utf16()` and fold each `u16`, per the contract's pseudocode. Every current vector is
  ASCII-only, so this is **latent** — a Rust harness will look green and diverge the first time a non-ASCII
  key is added. Pin it with a unit test on the hash function against a non-ASCII input rather than relying on
  the corpus to catch it.
- **Marker space-padding is part of `expectedHtml`.** No trimming anywhere in the emit path.

**Parser choice is a black box, not a fork** (`we:docs/agent/platform-decisions.md#ssr-external-io-standard-renderers-conform`
— the contract's own Non-goals cite it): html5ever/scraper is an implementation detail, and only externally
observable bytes are graded. Do not open a fork for it.

**The harness reads the JSON, never re-derives it.** Vendoring or transcribing the vectors into the Rust tree
would create a second authoring home that goes stale silently; the runner must load
`we:conformance-vectors/webdirectives-ssr.vectors.json` from the WE checkout (or a pinned copy fetched at
build time), and the CI step must fail loudly if it cannot find it — a harness that silently grades zero
vectors is the worst outcome, because it reports green.

**PIN THE FILE LAYOUT — two open children already lease specific paths.**
[#2761](/backlog/2761-native-rust-ssr-renderer-for-each-directive-keyed-empty-count/) (`for-each`) and
[#2764](/backlog/2764-native-rust-ssr-renderer-resource-loader-defer-directives/) (`resource:loader` +
`defer`) are both `status: open`, both ride on this slice, and both declare `scope:` as exactly
`frontierui:plugs/webdirectives/ssr/rust/src/renderer.rs` and
`frontierui:plugs/webdirectives/ssr/rust/tests/conformance.rs`. This card creates the tree, so **whatever it
names those files becomes their lease** — and a mismatch means the dispatcher's overlap prediction for both
children is wrong from the day they are queued.

So this slice must do one of two things, explicitly, and say which:

- **Adopt** `src/renderer.rs` + `tests/conformance.rs` as the real layout (the per-directive match arms live in
  `src/renderer.rs`; the harness runner is driven from `tests/conformance.rs`), or
- **Choose a different layout** — and then update `#2761` and `#2764`'s `scope:` in the same change, so the two
  leases name files that exist.

Do not leave it implicit. The sibling foundations (#2383 .NET, #2368 JVM) each split the renderer, the parser
shim and the harness across several files rather than one, so "it will obviously be `renderer.rs`" is not a
safe assumption — check the .NET tree's actual file set before deciding, and reconcile.

**Mirrors the .NET foundation #2383** in structure and in grading bar. One deliberate addition beyond what
#2383 and #2368 required of their own foundation slices: the `key-hash` unit test in `## Done when` item 3.
It is added here because the UTF-16-vs-UTF-8 divergence is a *Rust-specific* trap that the corpus cannot
catch (every current vector is ASCII-only), not because the sibling cards were deficient. The Node reference
oracle (`frontierui:plugs/webdirectives/ssr/nodeReferenceRenderer.ts`) stays the semantics tiebreaker.

## Done when

1. **Executable** — `cargo test` in `frontierui:plugs/webdirectives/ssr/rust/` is green and includes the
   cross-language conformance runner, which loads
   [we:conformance-vectors/webdirectives-ssr.vectors.json](conformance-vectors/webdirectives-ssr.vectors.json)
   and byte-compares the renderer's output to `expectedHtml` for every vector it claims. Fails before (the
   subtree does not exist); passes after.
2. **Executable** — the run reports **`failed: []`** for all five ✔ vector ids above, by id, and the
   remaining five report as explicitly *not-yet-implemented* rather than silently passing or being skipped
   without a name — a runner that grades zero vectors must exit non-zero.
3. **Executable** — a Rust unit test pins the `key-hash` DJB2 implementation against a **non-ASCII** key
   (e.g. a key containing `é` and an astral-plane character), asserting the UTF-16-code-unit result the
   contract's pseudocode specifies. This fails on the naive UTF-8-bytes port, which every current corpus
   vector would pass.
4. **Executable** — the repo CI workflow (`frontierui:.github/workflows/ci.yml`) runs that `cargo test` step
   alongside the existing JVM conformance step, and a deliberately-broken renderer (one byte off in a marker)
   turns the CI step red.
5. **Observable** — the file layout this slice creates matches the `scope:` leases on #2761 and #2764 — one
   `ls` of `frontierui:plugs/webdirectives/ssr/rust/` shows the files those two cards name, or those two cards'
   `scope:` fields are updated in this same change to name what was actually built. Neither card is left
   pointing at a path that does not exist.
6. **Observable** — the Rust tree contains **no** copy of the vector corpus: the runner resolves
   `we:conformance-vectors/webdirectives-ssr.vectors.json` at run time. One `grep` for a vector id string
   across the Rust subtree returns only the loader path, never inline expected HTML.
