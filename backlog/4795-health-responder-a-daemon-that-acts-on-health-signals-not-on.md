# Health responder: a daemon that acts on health signals, not only reports them

Prepare a separate, bounded responder for the operator request of 2026-10-02: “we need a daemon that will actually act on the health signals”. The watch detects and owns episodes; the responder acts through existing actuators, records its decisions, and escalates what it cannot safely resolve. This card is the implementation brief for all child stories below. Preparation changes backlog cards only; it neither enables a daemon nor authorizes a live repair.

The original operator digest named drafts #3336/#3311, unlabeled post-heal PRs #3239/#3389–#3392/#3463/#3471, #3432's approximately 17 review runs without an advisory, unattended red #3373, #3415 spending heal attempts on reportedly unrelated failures, and stranded finished-job lanes. The replay evidence below distinguishes observations from those reported causes. The requested invariants are binding: no approval, no removal of `review:human`, no gate bypass, no force-push, bounded actions, a kill switch, shadow first, and per-smell enablement.

## Design

**Prepared contract, not a claim of shipped behavior.** All “must” statements and numerical responder budgets below specify new work. References describe the current tree inspected on 2026-10-02; the existing source remains the authority when a comment and executable branch disagree. Runtime observations and GitHub events are explicitly identified as external evidence, not attributed to source code.

**Watch detects; responder acts.** The watch already has the detection registry, hysteresis, diagnoses, investigations, filing, and reporting. Its default is `mode: shadow`, `investigateDispatch: false`, `fileDispatch: false` (we:scripts/conveyor/health-watch-core.mjs:41). These are three distinct settings: `planActions` permits investigation/filing when their own switches are true even in shadow (we:scripts/conveyor/health-watch-core.mjs:461). Shadow does NOT mean silent: `NOTIFY_EVEN_IN_SHADOW` currently lists 16 smells, and the real desktop send is wired (we:scripts/conveyor/health-smells-notify-list.mjs:32; we:scripts/conveyor/health-watch.mjs:948). At the host census the health config file was absent, so the tree defaults, not an observed explicit live-mode setting, are the baseline. Do not flip any watch switch to enable the responder.

The responder must not import/call smell `evaluate`, parse daemon logs to find new incidents, or scrape PRs to discover work. It consumes only open episode subjects and acquires fresh facts for the nominated action's **preconditions**. The watch's disk-discovered registry has 41 descriptors (we:scripts/conveyor/health-smells/index.mjs:30). Extending detection for a missing signal belongs to that registry in the relevant action slice, never to a second detector inside the responder.

**Process shape.** Add a `health-responder` pass to the existing manifest and run it as its own launchd/supervisor process, from a dedicated registered daemon clone. Reuse `passDaemonLeaseKey('health-responder')`, yielding `<conveyor:pass-daemon:health-responder-lease>`, and the existing acquire/heartbeat/release implementation; never share the watch/review/fix lease (we:skills-src/conveyor/pass-daemon.mjs:67, we:skills-src/conveyor/pass-daemon.mjs:206; we:skills-src/conveyor/runner-lock.mjs:119). Use the watch plist as the deployment template, not a new supervisor (we:skills-src/conveyor/launchd/com.we.health-watch.plist.example:43; we:scripts/lib/daemon-clone-registry.mjs:50). Proposed cadence: 60 seconds after tick completion; 30-second tick ceiling, 10-second foreground child ceiling, bounded reads and at most one newly admitted action per tick. Long actuator work uses existing detached job/run records, not a synchronous wait. Publish boot revision, last-tick-completed, lease owner, mode and effective per-smell settings. Reload only between ticks, observing the five-minute restart floor. These requirements follow we:docs/agent/platform-decisions.md:5597 (#resident-daemon-reload-lifecycle) and we:docs/agent/platform-decisions.md:5744 (#daemon-jobs).

**Episode input contract.** Resolve the watch root through `healthDir`, not cwd (we:scripts/conveyor/health-watch-section.mjs:50). Read its atomic state snapshot and completed-tick stamp, then the matching JSON episode reports. The snapshot's open set is authoritative; the historical directory is not a queue. Closed history remains on disk and must never be replayed as live work. The shell writes reports before state and last-tick, so readers must read the completion stamp before and after the snapshot/reports, require it unchanged and equal to the snapshot’s completed tick, compare episode identity/status/samples/lastBreachAt, and retry a mixed generation without acting (we:scripts/conveyor/health-watch.mjs:964). A missing/corrupt snapshot, incomplete generation or watch completion older than 15 minutes holds all mutations; do not reuse the display reader's “never ticked, no episodes” fallback as proof of health (we:scripts/conveyor/health-watch-section.mjs:52; we:scripts/conveyor/health-watch-core.mjs:49).

Existing fields are `key = smell::subject`, `id`, `smell`, `subject`, `status`, `severity`, `action`, `breachStreak`, `cleanStreak`, `firstBreachAt`, `openedAt`, `lastBreachAt`, `samples`, `measure`, `summary`, `recommendation`, `tracked`, `remindedAt`; optional `escalatedAt`, `closedAt`, diagnosis/investigation fields. Pending episodes have no durable id. Open/flapping episodes receive an id composed from date, smell, subject and minute; closed episodes leave the active map (we:scripts/conveyor/health-watch-core.mjs:318, we:scripts/conveyor/health-watch-core.mjs:368, we:scripts/conveyor/health-watch-core.mjs:404). Scope and cadence live on the descriptor, not on the serialized episode. Measures differ by smell: a PR red episode contains failed check names and the last refusal, whereas a lane episode contains pool/lane facts; most PR episodes do **not** carry a head SHA (we:scripts/conveyor/health-smells/red-pr-unattended.mjs:46; we:scripts/conveyor/health-smells/lane-worker-without-lease.mjs:26). Freshly bind a nominated PR to repo + number + head, and a lane to pool + number + holder + lease generation; missing identity means refuse. Preserve the original `openedAt` as well as `id` to disambiguate a hypothetical same-minute filename collision.

**Pure core and thin IO shell.** Proposed core input: `{episodes, watchGeneration, subjectFacts, actionReceipts, budgets, config, now}`. Output per episode: `{decision: act|hold|noop|escalate, actionFamily, actuator, subject, expectedHeadOrLease, episodeIdentity, reason, evidenceRefs}`. Decision order: invalid/stale input → disabled/kill/pause → tracked/flapping hold → known host inhibitors → terminal hold/live owner → satisfied postcondition → budget/idempotency → current actuator plan → one action. The live-owner check is action-specific: a verified daemon session is required for a template nudge, and owner-token-checked release/resume may address only the responder’s own containment claim. Neither exception permits interference with a foreign fixer or bypass of a separate terminal hold. Unknown smells and unknown actuator result kinds hold and surface a diagnostic. Episode prose is display-only: never execute `recommendation`, free-text commands, paths, or actor assertions. The current watch itself separates declared diagnoses from rendered recommendations (we:scripts/conveyor/health-watch-core.mjs:470; we:scripts/conveyor/health-watch-core.mjs:377).

Write responder state under a separate pinned sibling of the health directory: an append-only action journal, atomic receipts/config, job references and last-tick stamp. Never edit the watch's episode JSON, history, silences or counters. Shadow may write only these diagnostic records; it has no GitHub, lane, claim, notification, or configuration mutation sinks. Include an injection seam that fails a test on any attempted external write. Actuator code remains single-owned; where a CLI currently sweeps all PRs/cards/lanes, add a target filter plus expected-head/lease precondition **there** before composing it. Never launch an unbounded whole-fleet `--apply` sweep for one episode. Existing promotion and CI dispatch currently loop all matching plan rows (we:scripts/operations/promote-draft-pr-dispatch.mjs:134; we:scripts/operations/ci-heal-pr-dispatch.mjs:245); orphan release and lease reaping also sweep (we:scripts/conveyor/orphan-claim-release.mjs:210; we:scripts/conveyor/lease-reaper.mjs:1406).

**Use the declared operation surface accurately.** The registry defines `compute/judge/confirm/effect` and declared input/step ownership (we:scripts/operations/registry.mjs:12). Existing `scaffold`, `stale-state`, `dispatch-lane`, `review-pr` and `verify` are registered by we:scripts/operations/run.mjs:37, we:scripts/operations/run.mjs:53, we:scripts/operations/run.mjs:74, we:scripts/operations/run.mjs:178, we:scripts/operations/run.mjs:216. Promotion/CI dispatch and review dispatch are existing operation-family modules, not all `we:scripts/operations/run.mjs` verbs; review dispatch explicitly documents that distinction (we:scripts/operations/review-dispatch.mjs:27). Thin responder action declarations must wrap these owners, validate bounded targets and emit audit records; no raw alternative label/git writer. Existing human-confirm operations, including stuck-session quarantine, remain unavailable to unattended automation (we:scripts/operations/run.mjs:196).

**Three missing seams, allocated now.**

1. Unlabeled post-heal PRs are not necessarily detected: `pr-no-owner` currently requires an `owed-elsewhere` or missing-run-cap refusal, and `review-label-conflict` does not classify zero labels (we:scripts/conveyor/health-smells/pr-no-owner.mjs:33, we:scripts/conveyor/health-smells/pr-no-owner.mjs:63; we:scripts/conveyor/health-smells/review-label-conflict.mjs:30). Slice 2 extends the watch's `pr-no-owner` result with a structured `missing-review-route` reason for an open automation-owned PR after a completed heal, no live owner/terminal hold, and absent review routing. The source history must establish automation ownership; an arbitrary unlabeled human PR is ineligible. Require four complete PR observations for both populations: the framework applies `openAfter` per descriptor, not per result, so retain the existing rule rather than silently claiming two samples suffice (we:scripts/conveyor/health-watch-core.mjs:360). Extend the existing watch PR probe to carry current head, trusted ownership/marker provenance and coverage status; it currently projects comments but omits head SHA (we:scripts/conveyor/health-watch.mjs:518, we:scripts/conveyor/health-watch.mjs:523). Record observed head and heal marker; partial/truncated/unreadable input is unknown, never an empty-label or absent-advisory observation. The shared label writer needs a narrow **restore-hold** target that uses the existing escalation rubric on the current diff: human tier → `review:human`, otherwise → `review:pending`; never accepted. Refuse any live verdict/hold, untrusted or incomplete diff, changed head, unresolved stand-down, or live fix claim. This is a new entry into the existing writer, not a second writer. Current `rearm` cannot do this: it requires changes/accepted (we:scripts/review-set-label.mjs:343). Reuse the producer's escalation derivation (we:scripts/pr-land.mjs:569) and the shared label IO boundary.
2. Slice 5 extends `repeated-pr-attempts` with a mandatory-referral subtype: three distinct trusted `mandatory-referrals-v1` run IDs for the same PR/head within two hours with no final verdict. Deduplicate records/edits by run ID; a completed whole review job is not required for a stuck referral. Unknown/partial/untrusted records refuse. This operator threshold supersedes the original five-completed-runs/60-minute proposal. The watch owns evidence collection and retains a bounded timestamped window. Required advisory coverage is a separate predicate: reuse trusted `ADVISORY_NOTE_MARKER`, reviewed basis and existing converted-advisory predicates in we:scripts/lib/advisory-labels.mjs and we:scripts/lib/review-escalation.mjs. A panel verdict or old red-team note is not current-head advice. #4922 defines trusted ruling provenance, label/withdrawal routing and operator-authorized resume.
3. A finished lane can be stranded even without pool starvation. Slice 4 adds a watch descriptor `stranded-lane` using existing stale-state/lease-reaper facts: terminal owned run/PR, positively dead worker and unchanged lease generation, two samples. Detection measures cleanliness and publication separately and includes local-only committed work; neither remote reachability nor release eligibility is required to emit a candidate. Proposed descriptor: `scope: host`, `cadence: every-tick`, `openAfter: 2`, `closeAfter: 2`, `severity: medium`, `escalateAfterMs: 3600000`, `action: alert`, `missingSubjectsUnknown: true`. Subject is pool identity plus lane number; measure carries holder, lease generation, terminal run/PR reference, worker-death proof, tree cleanliness, exact commit/verify head, local-only/remote reachability, main/open-PR coverage and observation time. An explicitly complete clean sample closes it; a missing/failed probe holds it, using the existing missing-subject contract (we:scripts/conveyor/health-watch-core.mjs:399). It emits candidate identity and evidence only. Release requires a clean tree and either no own commits or proof that every own commit is already on main. Any committed work not on main (unpushed, pushed with no PR, or reachable only through an open PR) is never released by this story and routes to #4926; when that adapter is absent/disabled, hold and report, never release. The responder still reruns the existing reaper's safety decision at action time. Live workers without leases are the **opposite** condition and must never be reaped (we:scripts/conveyor/health-smells/lane-worker-without-lease.mjs:20; we:scripts/conveyor/lease-reaper.mjs:677).

## Safety

1. **Independent settings.** Proposed responder default: shadow, no enabled smells, external sinks absent. Slice adapters can land and be tested while all mutations remain disabled. A per-smell setting can only select an implemented catalogue row; unknown values refuse. Enabling a responder family never flips the watch's investigation/file switches; investigation and filing additionally require their corresponding watch switch and shared receipt. All operator-added families below remain disabled until slice 6 proves their own canary. `tracked` episodes hold mutations as well as alerts; flapping episodes hold pending operator inspection. The existing silence/flap semantics are owned by we:scripts/conveyor/health-watch-core.mjs:417 and we:scripts/conveyor/health-watch-core.mjs:407.
2. **Caps survive restart, head changes and repeated episodes.** Atomically reserve A1/P plus family budget before invoking any mutation. Count attempts including timeouts/refusals after submission, not only successful returns. Existing CI/review comments remain the authoritative lower actuator floor; the new journal is only the responder's additional budget. Different smells pointing at one PR share a per-subject action lock and caps; different episodes for the same head cannot reset the family receipt. Head changes allow a new head-bound decision but never reset the rolling PR/hour/day totals. Zero automatic retries after ambiguous writes. Read the postcondition and durable actuator receipt first; if neither can settle what happened, escalate. Persist `prepared → submitted → confirmed|refused|unknown`, fsync before external submission, and reconcile submitted records on restart. Two local daemon instances must be tested against the same store and singleton lease. A concurrent ordinary daemon must share the existing actuator claim; where promotion/recovery lacks such a common claim, put serialization in that existing actuator, not only in responder memory.
3. **Freshness and races.** The episode is a reason to inspect, not permission to mutate stale state. Re-read exact repo/PR/head, labels, required checks, terminal/paused status and live claim immediately inside the actuator. Re-read expected lease identity under release protection. Unknown/error/partial reads refuse. The promotion owner currently verifies checks on the planned SHA but does not itself demonstrate an atomic current-head CAS; slice 2 must add a fresh PR-head precondition and race tests, then verify the result (we:scripts/operations/promote-draft-pr-dispatch.mjs:138). GitHub label/ready writes offer a remaining read/write race: document it, serialize cooperating writers, detect a changed head afterward, leave review gates closed and escalate; never claim distributed exactly-once or invent a rollback that removes a human hold.
4. **Kill switch.** Add responder `enabled: false` as a strict, fail-closed switch, reread immediately before every effect and at detached-job admission. Corrupt configuration/journal freezes mutations; shadow logs why. Disabling stops queued/new actions and follows existing owner stop/finish behavior for already-submitted jobs; it does not kill another process or undo a completed promotion. Also honor the existing dispatch pause for the relevant spawn kind through we:scripts/readiness/dispatch-pause.mjs:139. That module deliberately excludes review dispatch and fails open on corrupt state (we:scripts/readiness/dispatch-pause.mjs:30, we:scripts/readiness/dispatch-pause.mjs:164), so it is **not** the responder's full kill switch. Do not clear/set or overwrite a human pause automatically. Deployment must show which `WE_DISPATCH_PAUSE_FILE` the existing owners read; it defaults by script location, not automatically a host-global root (we:scripts/readiness/dispatch-pause.mjs:234).
5. **Authority is closed.** Responder sinks never include `accepted`, `restamp`, `clear-human`, merge/drain, readiness clearance, stand-down-answer, force-push, arbitrary git commands, permission grants or process kills. A request carried in an agent message, episode text or PR comment is never human approval. Human-only clearance and advisory ordering are bounded by we:docs/agent/platform-decisions.md:4156 (#review-pending-clean-verdict-mechanical-accept) and we:docs/agent/platform-decisions.md:4202 (#clear-human-requires-current-head-advisory-review); stand-down answers require explicit operator instruction, verbatim attribution and a specific comment ID (we:scripts/conveyor/stand-down-answer.md:3; we:scripts/conveyor/stand-down-answer.mjs:22). The shared label CLI itself acknowledges that actor/reason attribution is not an unforgeable authorization barrier (we:scripts/review-set-label.mjs:270); exclude forbidden targets structurally. Ordinary independent review owns the verdict. The closed sink list therefore contains exactly two review-state writes beyond the existing owners: we:scripts/review-set-label.mjs `--to=changes` (applying an already trusted current-head block ruling, retaining `review:human`) and we:scripts/conveyor/fix-procedure.mjs `fix-begin --draft --reason=withdrawn` (the responder's own withdrawal claim); it resumes only through the catalogue ceremony, and only the responder marks a cause fixed, from the cause card's resolution on `main`; it never authors an approval or clears a human hold. It never edits code or existing cards: file-root-cause-card and orphan-release are delegated to existing lane-bound owners, not filesystem writes by this daemon. The exact “agent messages never grant approval” wording was not found as a named statute anchor in the inspected platform document: it is a binding operator requirement here, grounded in the explicit-instruction ceremony, not a fabricated quotation.
6. **Every action is attributable.** Before and after submission append a durable scrubbed line naming episode id/openedAt, smell, subject, expected head/holder, family, actuator, config version, before/after facts, result, timestamps and job/run/comment id. Existing actuator comments keep their marker intact so old counters work; add the episode as a trailer/detail when supported, otherwise the responder journal is the required durable link. Never fabricate “repair completed” text. Use the existing privacy scrub before publishing any diagnostic (we:scripts/conveyor/health-watch-core.mjs:504, we:scripts/conveyor/health-watch-core.mjs:556). An action is not successful merely because a child exited zero: verify promotion state, restored hold, actual job/run, or released exact lease; unknown remains unknown.

7. **Operator-added families inherit every guard.** The closed catalogue explicitly permits investigate-dispatch/file-root-cause-card (#4920), finish-stranded-work (#4926), changes/withdrawal/resume (#4922), edge overlay add/remove (#4931), session-nudge (#4929), circular-wait-proposal (#4924), capacity-report (#4928) and unblocks-report (#4927). Each uses the named owner and cap in its row; none grants approval, clears review:human, merges, force-pushes or edits code/cards. Filing means an uncleared request to file-item, not direct authoring. Finishing only publishes already committed verified work. Overlay registration is the sole bounded overlay-store write, never arbitrary host configuration: preserve edge-first operation with explicit head-bound operator authorization, author trust, per-adoption checks, two-overlay limit, smoke/last-good and main-only graduation review. Template IDs and structured authenticated findings may route actions; arbitrary evidence text cannot. Circular waits and capacity holds remain proposal/report only. Every mutating step has shadow, kill/pause, freshness, receipt and budget checks, and no family is enabled without #4932's per-family proof.

## Escalation

The operator gets **one high-severity message per episode**, in plain language: what is stuck, what the responder attempted or why it refused, the exhausted limit/required decision, and links to the PR and episode/action report. Example: “PR #3415 has used all three CI repairs and is still failing. No further repair was started. Inspect the shared test failure before authorizing new work.” Medium/low episodes remain in the report and HEALTH queue; the watch owns severity and duration escalation. The three duration-policy smells start medium and become high after an hour of continuous breach, not immediately because their names appear on the shadow notify list (we:scripts/conveyor/health-smells/draft-not-promoted.mjs:34; we:scripts/conveyor/health-smells/red-pr-unattended.mjs:28; we:scripts/conveyor/health-smells/repeated-pr-attempts.mjs:10; we:scripts/conveyor/health-watch-core.mjs:387).

Keep the watch's existing desktop sender as the **single notification owner**, and its operator-queue HEALTH section as the read surface (we:scripts/conveyor/health-watch.mjs:948; we:scripts/conveyor/health-watch-section.mjs:60). The responder writes a separate escalation intent/result the watch can join into its report; it never sends a competing desktop message. Slice 6 adds a shared durable notification receipt keyed by full episode identity and a final high/untracked check at delivery. An initial watch alert consumes the same receipt, so a later action failure updates the report/queue without another ping. Existing `remindedAt` is a transition, not a durable delivered receipt; current code allows a four-hour reminder and silence-expiry notification (we:scripts/conveyor/health-watch-core.mjs:430, we:scripts/conveyor/health-watch-core.mjs:481). For responder-enrolled episodes, the operator's stricter one-message rule here suppresses additional sends through the shared receipt. Preserve other watch behavior. Do not backfill a burst of historical alerts on upgrade: existing episodes get an explicit migrated/unknown-delivery receipt and queue-only status. If send outcome is ambiguous, do not retry automatically; a clearly pre-send failure may be retried without claiming it was delivered.

High auth/rate-limit/host-load episodes inhibit relevant responder actions; the existing throttle and owner handle recovery. Only the catalogue investigate-dispatch/file-root-cause-card families may request diagnosis or filing through their existing owners, with class/day caps, duplicate suppression and scrubbed untrusted evidence; never directly edit code/cards or auto-clear a request. Existing watch investigations/filing remain separately gated under we:docs/agent/platform-decisions.md:5703 (#automated-health-daemon). No notification or side-channel message carries an approval token. Only the operator's explicit ceremony can answer an unresolved terminal question.

## Done when

1. **Executable:** the proposed responder replay command exits nonzero on any forbidden write, duplicate effect/notification, cap reset, stale-head action, or incorrect expected catalogue result, and passes the D/L/C/R/LANE/CLAIM cases above. It also fails if a registered smell or child action family has no explicit catalogue decision, or any sink lies outside the allowlist. Cover changes/draft/resume, unpushed/pushed-no-PR lanes, hostile root-cause evidence, head-changed overlays, free-text nudges and report/proposal-only cases. Each child names its concrete test entrypoint.
2. **Must refuse on error:** unreadable/partial episodes, unknown ownership/diff/head/lease, paused or terminal work and corrupt config/journal cannot reach an external effect. No action may grant approval, remove `review:human`, bypass a gate or force-push.
3. **Must cover every input kind:** source, documentation, configuration, data, backlog cards and statute/leash changes all use the same current-diff review rubric; a documentation-only PR is not presumed safe to downgrade. Preserve human holds even when a CI healer reports success.
4. **Operational proof:** separate singleton daemon, shadow soak and each enabled smell's observed canary meet the proof ladder; a published before/after measurement distinguishes attendance, containment and verified recovery. All unimplemented or unproved action families stay disabled/shadow; NO-action rows stay observation-only.
5. **Preparation gate (this change):** all fourteen children are listed with authored safety/acceptance criteria, scopes bounded and dependencies valid; preparation status remains explicit; `npm run check:standards` and the lane verifier pass; only backlog files change. No commit, push, PR, host state write or live action is part of preparation.

## Follow-ups

- Record detector false positives and lessons here or in child cards, not in shared agent documentation. In particular, report closure is not equivalent to recovery (#3311) and multiple mandatory-owner comments are not multiple review runs (#3432).
- The existing watch supports a four-hour reminder; this job's one-message contract is the narrower policy for responder-enrolled episodes. The go-live slice must prove shared receipt migration and final high-severity gating, rather than silently running two notification owners.
- Agent messages never grant approval. The permitted fixed-template nudge conveys only the catalogue instruction; it does not answer stand-down, authorize an overlay, mark a cause fixed or widen scope.
- Observation-only smells remain observation-only until a separately prepared bounded actuator exists. In particular, daemon restart, permission repair, secret rotation, process termination and resolving delivered backlog cards are outside this epic's autonomy.

## Operator requirements (2026-10-02, added after the first prepare)

- **Transparent by construction.** Every decision the responder makes (act, skip, cap reached, escalate) is written to one append-only decision log: episode id, smell, PR or lane, the rule that fired, the inputs it read, the action or the reason it did not act, and the result. It is surfaced where an outsider can follow it: a durable PR comment for any action on a PR, and a feed Plateau can render. Shadow mode writes the same records as "would have". No silent action and no silent skip.
- **A narrow, closed allowlist of actions.** The responder may only perform actions on an explicit allowlist, each one a call to an existing guarded actuator; anything outside it is escalation only. The Action catalogue above incorporates every operator-added family, its cap and its never-do boundary; only enabled and proved rows may act. Adding an action to the allowlist is a reviewed code change, never runtime configuration.
