# Decision: permission profiles for all agent work (scoped by default, wrapper-run requests)

## Prepared digest — recommendation, not a ruling

**Recommend preventive, wrapper-owned source-write scopes for agent jobs, with narrow scope requests adjudicated under project policy and activated only after an atomic reservation check; park long or contagious waits after preserving work and context, releasing the job’s own scope.** Preserve broad sandboxed inspection, the existing stricter step/reviewer rules, and post-run checks. The operator's 2026-09-30 direction (strict file rights soon, full containers after builder stabilization) is compatible with this recommendation **only if “read-only” is enforced against every worker write channel**, not merely by prompts or reversible file modes. No implementation or backend has been approved by this preparation.

Two policy forks and a configurable conflict-response dimension remain: the minimum guarantee a job profile promises, and who may expand its authority; the dimension selects accept-overlap, wait, or park for each conflict. Filesystem permissions, macOS sandboxing, and containers are interchangeable or composable enforcement mechanisms, not competing WE standards. The axes are grounded below in the actual post-run refusal, provider launch flags, scope matcher, and verification writes. Research is inline at the operator's explicit request; no separate report, research topic, hold file, build child, or shared-doc edit is created.

| Fork | Recommended default | Main alternative | Confidence |
| --- | --- | --- | --- |
| 1 — permission guarantee | **(a) Prevent edits outside the granted source scope before effect; fail closed if unsupported** | (b) Permit lane-wide edits and refuse the resulting diff afterward | High on guarantee; medium on first backend feasibility |
| 2 — widening authority | **(a) External wrapper grants within the operator ceiling; agent only requests** | (c) Agent self-authorizes an extension | High on authority; medium-high on automated-grant configuration |
| Conflict-response dimension — not a third fork | **Wait briefly; park if over five minutes, ETA unknown, or retained scope blocks others; accept only explicitly authorized low-risk overlaps** | Project overrides within the same authority ceiling | Proposed thresholds; lifecycle integration unimplemented |

## Fork 1 — is declared source scope an enforceable permission or a post-run acceptance rule?

**Fork-existence:** the same job cannot both be permitted to change an ungranted source path and be guaranteed unable to change it. A detector can compose with prevention, but cannot implement that guarantee: the current runner examines the diff only after the worker returns (we:scripts/operations/probation-build-run.mjs:401, we:scripts/operations/probation-build-run.mjs:441).

- **(a) Preventive profiles.** The wrapper derives a profile from the assigned role and approved work; source paths outside the grant are readable but unwritable. The grant covers create, replace, delete, rename, link, permission changes, native file tools, subprocesses, and delegated tools. A provider/backend that cannot demonstrate this profile cannot run under its name: reroute or park. Reads stay broad within the authorized sandbox; external mutations remain typed operations. This prevents accidental extra edits and scope-based concurrency drift, but requires genuine mediation and handles unsupported providers explicitly.
- **(b) Observational profiles.** Keep lane-wide editing, instructions and final diff refusal. This accommodates today's providers and arbitrary editor saves, but detects the error after effort has been spent and cannot undo effects outside the captured diff. *Rejected as the proposed default*, retained as the description of legacy behavior while migration is ungraduated.
- **(c) Prevent only planner-step writes; leave other jobs observational.** Respects the existing step boundary but leaves prepare, heal, whole-item build, and investigation-to-edit transitions with a different guarantee. *Rejected as the target policy*: role-specific permissions are useful; silent differences in whether permissions are enforced are not.

**Recommend Fork 1 (a): enforce the approved write set, retain post-hoc guards as independent evidence, and record actual enforcement capability per run.** Do not advertise all-provider prevention on ratification. Existing runners remain explicitly legacy until live canaries pass; new “scoped” dispatch must fail closed rather than falling back silently. This is an operational rule for WE's agent machinery, not a plug/block/protocol or a new WE↔FUI contract.

The amendment is deliberately narrow: extend the in-lane write boundary beyond planner steps. Do not turn the 72.2% read/inspection majority into an all-command allowlist. That measurement and the external-mutation rule live in we:docs/agent/platform-decisions.md:4691, anchor `#agent-mutations-through-typed-operations`. The step's no-free-shell rule remains a stricter exception (we:docs/agent/platform-decisions.md:5558). The tool-bearing reviewer keeps its separate operations-only/container requirements (we:docs/agent/platform-decisions.md:5234, anchor `#reviewer-tool-surface-and-containment`).

Skeptic: SURVIVES-WITH-AMENDMENT — the independent prep skeptic found the advisory-scope and Gemini-residual conflicts. This proposal explicitly amends those limits, separates permissions from clone ownership, and preserves stricter review rules.

Screen: clear — a separate fresh-context reviewer confirmed this is operational governance, not a WE standard or backend implementation choice; prevention versus observation remains a correctness difference even with zero implementation cost.

## Fork 2 — who may widen a grant?

**Fork-existence (forced invariant):** an agent cannot both enforce its own upper authority bound and unilaterally enlarge it. Agent-authored scope is input to external adjudication, not authorization. Automatic versus human approval is a supported configuration of that external authority, not a competing fork.

- **(a) Bounded mechanical grants.** The wrapper may grant an exact extension within an operator-approved profile ceiling, after fresh conflict checks and atomic reservation. Contention follows the conflict-response dimension below; policy exceptions escalate. Keeps ordinary omitted-test corrections flowing, at the cost of making the reservation service and its audit record authoritative.
- **(b) Human approval for every added path.** Gives the operator maximum per-request control and is a valid restrictive profile. It adds interruption even when authority and disjointness are mechanically established. Supported as a stricter profile setting; not an excluded architecture. The recommendation is to use it where judgment remains, rather than for every ordinary exact-file extension.
- **(c) Agent self-expansion or “edit now, justify later.”** Allows a model to mutate its own permission boundary and race other jobs. *Rejected*: an agent-authored card or manifest is a request, never proof that authority expanded.

**Recommend Fork 2 (a): the external wrapper alone activates rights within an explicit operator ceiling; Fork 2 (b) is its human-only configuration.** Existing per-program overlap policy already supports configurable wait/ask/force (we:scripts/readiness/scope-policy-config.mjs:10). An operator may preauthorize a narrowly described force policy; absent that authority, a worker request to force escalates. No worker can invent that ceiling. Use the existing scope normalization/overlap semantics (we:scripts/readiness/scope-lease.mjs:248; we:scripts/readiness/scope-lease-live.mjs:154), not a second string-prefix implementation. Existing `wait`, `ask`, and `force` outcomes are reusable vocabulary; their pure return value is not an atomic grant or permission change.

Proposed lifecycle, not an existing callable operation:

1. **Request:** submit job/step identity, expected grant revision, exact repo-qualified paths, requested actions, and reason through `request-scope`. Do not submit a shell command. Reject traversal, unresolved repo aliases, symlink escapes and ambiguous case aliases; check both rename endpoints and the nearest existing ancestor of a new file. Directory grants reserve their whole subtree.
2. **Evaluate:** wrapper authenticates the caller and live lease; tests the profile ceiling and task purpose; combines other running jobs' declared plus observed scopes with open PR changed-file scopes and pending reservations. Exclude only the caller's own identified lease/PR, not every job sharing its parent item. Missing/stale PR data or an unscoped active writer means unknown/held, never “no overlap.”
3. **Grant:** under one reservation lock/transaction, recheck revision and conflicts and reserve the extension before exposing write permission. Every dispatch/start, PR admission and scope extension must use that same authority. Snapshotting GitHub alone cannot lock out a human or external PR: reconcile at grant/start and drain, retain final overlap checks, and state that unmanaged actors are outside the scheduling guarantee.
4. **Activate:** stop/quiesce the worker and delegated tools, install the new policy, verify it, then resume with a new revision. A static sandbox may require restarting the process. Publish `granted` only after installation succeeds; failure leaves old rights in force and releases the pending reservation. Revocation must end old processes/open writable handles, not merely rewrite a settings file.
5. **Conflict response:** return blocker job/PR IDs and the exact intersection, then select accept-overlap, bounded wait, or checkpoint-and-release park using the policy dimension below. Requested paths remain denied until an explicit grant activates. An ordinary open delivery PR retains its reservation after its worker exits; parking must explicitly withdraw it from active admission before releasing that scope.
6. **Escalate:** protected policy/hooks, broad directory/repo grants, cross-repo expansion, profile changes, uncertain authority or force-overlap outside the configured ceiling require an operator decision. Exhausted waits automatically park under the configured policy; they do not inherently need a human. No reply means pending. An authorized force records conflicting owners and drain reconciliation; it does not grant new external-operation authority or disable isolation. Release grants only after worker termination and final diff capture; quarantine a lane whose cleanup cannot be verified.

For #4389, the concrete request would name `we:scripts/__tests__/merge-ai-prs-merge-failure-isolation.test.mjs`, reason “required by the card's Test plan,” action create/write. A nonoverlapping, ordinary test addition within the job ceiling is granted before editing; if another running job or open PR owns it, the project conflict policy chooses the response below. Shared agent docs are not incidental test outputs and need their own request. A request to expand scope must update the wrapper's accepted dispatch/card scope through an authorized operation too; otherwise today's final checker would still reject the newly allowed path.

Skeptic: SURVIVES-WITH-AMENDMENT — the independent prep skeptic dissolved automatic-versus-human approval into configuration; the actual invariant is external authority versus self-widening. Added task relevance, participating-actor limits and external-PR reconciliation.

Screen: clear — a separate fresh-context reviewer confirmed external versus self-authorized grants is a substantive authority difference; automatic versus human approval is correctly configuration.

## Policy dimension — what happens when a scope request conflicts?

**Classification: supported project configuration, not a third either/or architecture fork.** All three responses can be appropriate in the same project. The invariant proposed for ratification is external, recorded adjudication with bounded waiting and lossless release/resume; the response is selected per request. This extends the existing advisory policy into the proposed preventive grant lifecycle. It does not claim the lifecycle already exists or silently replace the current defaults.

Operator feedback (2026-09-30, verbatim):

> Seem a bit light, light how to prevent a or from blocking a scope : pr ask for scope from preparation, find it needs more, ask for it, scope conflicts, we look at the project configured policy, might either accept and just resolve conflicts, might wait or might park, and each might be used depending on criteria like how long it would block as this or would block its own scope without doing any work so parking the work and context for later could often be the best

### Whole flow and the three supported responses

A job starts with the exact scope accepted from preparation. It discovers a necessary additional file, stops before editing that file, and submits the extension with its current grant revision. The wrapper checks purpose and authority, then compares the requested scope against running jobs, pending reservations and open PRs. It records every blocker and overlap, loads the project policy, and selects a response. Even an authorized overlap goes through reservation and permission activation; it never permits two workers to share one mutable checkout.

| Response | Execution, ownership and tradeoff |
| --- | --- |
| **accept-overlap** | Grant the extension within the operator ceiling despite the named overlap, recording both owners and a drain predecessor/successor edge. This corresponds to existing `force` plus `resolveAtDrain`, not a bypass of review. Parallel work can continue, but reconciliation is owed by the successor job's author/fixer. After the predecessor merges, that agent rebases/cherry-picks onto the resulting head, resolves content conflicts, runs affected checks and obtains review for the new diff before the serial drain may merge it. The wrapper names a recovery fixer if the original worker has exited. Unresolvable conflicts or conflicts requiring operator policy/design judgment park for the operator. |
| **wait** | Keep the worker and its existing grant; requested paths stay denied. Continue useful work in the old scope if any remains. Retry on blocker changes or a bounded timer, preserving a single cumulative budget. This avoids checkpoint/restart cost for short blocks, but an idle worker can monopolize its own files and block a third job. Re-evaluate that harm on every retry; expiration or new contention selects park. |
| **park** | Quiesce the worker and descendants, checkpoint BOTH code and resumable context, verify durability, record a requeue entry, then revoke rights and release ALL its active source reservations and its lane lease once safe. A parked job retains recovery identity and queue age, not ownership of its files. It resumes after the blocker clears by acquiring a fresh lane/grant, restoring the checkpoint onto the current base, and revalidating scope, tests and review. This frees others immediately after safe checkpointing, at the cost of restart/reconciliation work. |

**Drain ordering proposal:** honor existing dependency/topological order first; for otherwise independent accepted overlaps, the pre-existing owner precedes the newly admitted job. Record edges before activation, reject cycles, and keep disjoint work drainable. Several blockers all precede the successor. Never let a newly urgent job reverse an already recorded edge automatically. If a predecessor closes without merging, reconcile against current main and re-evaluate the edge; missing status is not clearance. Existing drain dependency ordering is observable in we:scripts/lane-drain.mjs:262 and its sole-writer resume route in we:scripts/lane-resume.mjs:465. New scope-overlap edges are a proposal, not an existing drain input. Conflict fixes reuse the agent-dispatch and re-review path in we:scripts/conveyor/parked-pr-conflict-watch.mjs:24; the settled rule is we:docs/agent/platform-decisions.md#parked-pr-conflict-dispatched-not-scripted.

### Recommended project default and concrete decision inputs

**Recommend wait only for a credible remaining block of at most five minutes, with no downstream contention on the retained scope; park immediately for a longer or unknown wait, or whenever the waiting job would hold its own scope idle and block another eligible job. Accept-overlap only under an explicit project allowlist and verified low-risk diff.** Five minutes is a proposed initial operating threshold, not a measured completion-time percentile. Limit waiting to five elapsed minutes and five scheduled retries, whichever comes first; events may trigger earlier re-evaluation without resetting either budget. A newly eligible downstream waiter ends the wait early. Parking is the usual response to human-review uncertainty. A large amount of finished work argues for a careful checkpoint, not unlimited ownership.

| Input available in the repo | Proposed use and uncertainty handling |
| --- | --- |
| Blocker phase/progress: live owner/claim, PR head, review labels, required-check state, elapsed waiting/park episode | Fix scheduling exposes `waitingSince` and `reviewHuman` (we:scripts/conveyor/reconcile-fix-dispatch.mjs:1454); PR park age uses label-event time (we:scripts/conveyor/parked-pr-progress-watch.mjs:155); CI state is shared by resume/drain (we:scripts/lane-resume.mjs:447). An active final check with a fresh owner estimate can justify a short wait; human review, red CI or stalled work usually cannot. No reliable remaining-time estimator is established by these sources: record an explicit fresh ETA and its source/confidence when available, otherwise **unknown → park**, never infer “almost done” from age alone. |
| The waiting job's own scope and downstream demand | Intersect its retained effective scope with other eligible queued requests. Effective scope is predicted ∪ observed (we:scripts/readiness/scope-lease-live.mjs:60); builder holds already expose live-lane and same-tick rival overlap (we:scripts/readiness/dispatch-plan.mjs:602). Record which third jobs are blocked and whether any useful in-scope work remains. Idle retained scope with downstream demand wins over a short ETA or expensive context. |
| Overlap size and risk | Use normalized path intersections and actual diffs, not file count alone. The shared matcher feeds we:scripts/readiness/scope-lease.mjs:248 and we:scripts/readiness/scope-lease-live.mjs:154. Proposed automatic acceptance is at most one explicitly allowlisted test file with independent appended cases, no shared setup/import rewrites, no generated snapshot and no semantic coupling. Append-only text can still conflict at EOF: this is low risk, not conflict-free. Broad directories, shared agent docs, policy files and unknown diffs cannot auto-accept. |
| Priority/tier and age | Builder input is already rank ordered (we:scripts/readiness/dispatch-plan.mjs:353); fixer fairness uses waiting episode, then human-review ties, then PR number (we:scripts/conveyor/reconcile-fix-dispatch.mjs:1454). Preserve those inputs and original queue age on park/resume; priority chooses among eligible jobs, never enlarges the permission ceiling. |
| Work completed and context replacement cost | Checkpoint head/WIP SHAs, changed/untracked files and salvage metadata provide observable progress (we:scripts/lib/lane-salvage.mjs:403, we:scripts/lib/lane-salvage.mjs:465). Tests already run, learned constraints, plan and estimated reconstruction time come from a persisted agent handoff. Lines changed do not establish percent complete. High reconstruction cost favors a short bounded wait only while nobody else is blocked; otherwise save richer context and park. |

**Configuration proposal:** resolve an operator-owned project policy, with per-program overrides restricted by the project ceiling; persist the effective revision on every request. Reuse we:scripts/readiness/scope-policy-config.mjs:47 and its validation at we:scripts/readiness/scope-policy-config.mjs:77 for the existing `overlapAtLaunch`, `breachMidBuild`, `retryBound` settings. Currently these default to `wait`, `pause`, and one breach retry, and unknown keys are rejected. A separately validated scope-request policy would add `maxWaitMs: 300000`, `maxWaitRetries: 5`, `unknownEta: park`, `parkIfOwnScopeContended: true`, and an empty-by-default accept-overlap allowlist (projects opt in specific low-risk test files). These fields and their project persistence/wiring are proposed follow-on work, not accepted keys today. Keep wait retries distinct from the existing breach-attempt counter: asking before a write is not a breach. `ask` remains escalation for an authority exception, with the job checkpointed and released while awaiting a human; no answer grants nothing. `force` maps to authorized accept-overlap. The existing breach `park` result is reusable vocabulary, not proof of a checkpoint or released reservation.

### Park means preserved work AND context, followed by actual release

Reuse the verified bundle/WIP/patch/index machinery in we:scripts/lib/lane-salvage.mjs:460 and we:scripts/lane-pool.mjs:3747, the redispatch salvage hints in we:scripts/lib/salvage-index.mjs:6, and the saved-alt-branch prompt in we:scripts/conveyor/fix-procedure.mjs:523. The concurrent-author pause already records head/alt/alt-SHA and re-arms on head movement or quiet time (we:scripts/conveyor/stand-down.mjs:77; we:scripts/conveyor/reconcile-core.mjs:297). Its wake signal alone does **not** prove a scope blocker released its reservation. Reuse the recovery artifacts and re-arm pattern, but use actual scope clearance for this policy.

The wrapper must save a branch commit or verified lane snapshot including uncommitted and untracked work, plus an explicit handoff: what was learned, constraints and decisions, current plan, completed steps/tests and results, remaining steps, denied extension/reason, blocker identities, base/head SHAs, and recovery instructions. Save a provider session identifier if available, but the handoff must stand alone when that session cannot resume. Existing salvage preserves files; it does not by itself capture the agent's reasoning context. Context must be an explicit durable artifact referenced by the same checkpoint. Bind it to item, attempt, repository and SHA so a later occupant's lane or an obsolete alt branch cannot be resumed accidentally. Preserve queued checkpoints beyond the salvage index's ordinary 14-day expiry (we:scripts/lib/salvage-index.mjs:9); pin or copy them into durable queue-owned retention before releasing the lane.

Ordering is safety-critical: stop all writers → write/verify code and context artifacts → persist an idempotent parked/requeue record → revoke source rights → release reservations and lane → mark parked/released. A failed checkpoint leaves an explicit recovery hold, never a false successful park or destructive reset. The existing reclaim path refuses live holders (we:scripts/lib/lane-salvage.mjs:147); do not invoke reclaim against a running job or weaken that gate. Reuse snapshot primitives under wrapper-controlled quiescence, then use ordinary lease release. On recovery from a crash between steps, verify artifacts and process termination before completing release exactly once.

An open PR requires special handling: merely labelling it parked/draft does not remove its changed-file overlap. Withdraw it from active delivery and persist a park identity recognized by **all** reservation/dispatch readers before releasing its scope; if that exclusion is unavailable, close the delivery PR while retaining its checkpoint branch and arrange reopen/replacement on resume. Otherwise it remains a blocker and must not be reported as successfully released. A checkpoint branch without an active delivery PR carries recovery data, not a live scope reservation. After release, remove the parked job from active fixer wait-order scope propagation too; retain its queue age without allowing it to block younger jobs indirectly.

Wake on blocker release/merge/close/cancellation, with a periodic bounded recheck for missed events. Requeue the SAME item/attempt with the checkpoint pointer; do not start duplicate workers. Atomically reacquire the full original-plus-requested scope against current jobs/PRs, restore only changes not already present, load the handoff, then continue remaining work. If contention persists, stay parked without owning scope. Resume-to-landing helpers such as we:scripts/lane-resume.mjs:465 do not substitute for resuming an unfinished agent plan.

### Serialization, deadlocks and the audit record

The fix daemon already emits **“waiting Nth behind #M”** and serializes build/fix claims plus older waiters (we:scripts/conveyor/reconcile-fix-dispatch.mjs:1438, we:scripts/conveyor/reconcile-fix-dispatch.mjs:1478). Builder scope-overlap holds are in we:scripts/readiness/dispatch-plan.mjs:602 and we:scripts/readiness/dispatch-plan.mjs:613. These are evidence for the scheduling inputs and queue presentation, not an implemented permission-extension service. Today's fixer ignores unknown-scope claims and exempts an item's own build claim; the proposed grant service must use authenticated owner identity and fail closed on unknown scope as Fork 2 specifies. Whole-clone acquisition still describes its file overlap as advisory (we:scripts/lane-pool.mjs:2211). Ratification would require reconciling these callers with the shared policy, not changing one pure return value and declaring enforcement complete.

Maintain a wait-for graph over reservation owners and PRs. Before adding an edge, detect cycles across both waits and drain precedences. Break a wait cycle by parking the lowest-priority participant, ties choosing the newest request then stable job ID; preserve its checkpoint and release its entire held scope. If that participant cannot checkpoint, hold/escalate the cycle visibly rather than granting unsafe access. Acquire expansions atomically, never partially while accumulating more locks. Stable queue age, bounded budgets, and removal of parked jobs from active blockers prevent indefinite hold-and-wait; age-based scheduling prevents repeated park/resume from starving the same job. Unknown owners never count as cleared. Repeated failed resumes stay parked with a surfaced recovery reason, not a hot retry loop.

Record every evaluation and transition: request/item/attempt/owner IDs; project and effective policy revision; old grant revision, existing/requested/intersecting paths and operations; blocker job/PR IDs and heads; snapshot timestamps/freshness; ETA/source/confidence and review/CI phase; own-scope downstream waiters; priority/tier/queue age; work/checkpoint/context cost; selected response, rule and rejected alternatives; authority/override actor; wait start/deadline/retry count; drain edges and named resolver; checkpoint/context refs and verification; revocation/release acknowledgements; wake condition and eventual resume identity/outcome. Missing observations are recorded as unknown. A `park` verdict alone is never evidence of release.

Concrete example: A holds file X from preparation and requests Y, owned by PR B. B has a fresh two-minute final-check ETA and nobody needs X: wait, retaining X. If job C then requests X, checkpoint A's work and context, release X, and let C run; A stays queued for Y. If B is awaiting human review with no ETA, park A immediately. If the only overlap is an allowlisted independent test append, the project may grant overlap, reserve B-before-A at drain, and assign A's fixer to reconcile and re-review after B lands. None of these responses authorizes A to widen its own grant.

### Backend alternatives and known occurrences

**Recommended implementation direction after ratification:** implement the grant/reservation contract once, then graduate one fully mediated host backend on the actual builder/provider pair. A whole-process macOS sandbox is a candidate on this host; it is not proven by an agy shell flag. If no host backend passes the canaries, move that provider to a container/VM or park it. Container delivery is separately scheduled, without deferring the policy contract or weakening the existing reviewer mandate.

| Approach | Guarantee and failure modes | Disposition |
| --- | --- | --- |
| Post-hoc refusal | Already shipped. Captures tracked/untracked diff problems after work; cannot prove that transient edits or writes outside the lane never happened. | Keep as backstop; insufficient for Fork 1 (a). |
| Same-user per-lane modes (`chmod`) | Denies straightforward writes but the owner can change modes back. Writable parent directories permit unlink/rename replacement; exact-file atomic saves need more than a file write bit. | Useful accidental-error signal, not a strict boundary. |
| Per-lane permissions with a distinct worker identity and wrapper-owned ACLs/parents | OS checks apply to native tools as well as shell. Must deny ownership/ACL changes and protect parent directory entries; creation/atomic replacement may need a broker. Separate identities must not share writable hardlinks or writable dependency/sibling trees. | Viable host adapter, conditional on save/create/rename and lifecycle proof; account/ownership management is real operational work. |
| macOS Seatbelt profile around the entire worker/tool process tree | Can constrain filesystem operations without changing the checkout's ownership. Escaping helper services, already-running native-tool daemons, symlinks, nested sandboxes, provider caches and exact-file saves need probes. Static-policy widening can require restart. | Candidate first host backend, never infer confinement from shell-only flags. Local `man sandbox-exec` marks the interface deprecated; avoid treating it as a portable long-term API. |
| Containers / VMs | Put workers and operation servers inside an OS boundary; support explicit mounts, resources and network policy. A fully writable lane mount still allows every lane file to change. Read-only checkout plus approved writable overlays/broker still needed; no broad host mounts, runtime socket, or publisher credentials. VM provides a separate guest kernel; a container's kernel boundary depends on its runtime. | Stronger isolation adapter; retain the same scope-request protocol. Do not pick Docker vs Apple vs another backend in this card. |

Primary prior art: the [OpenAI sandbox documentation](https://learn.chatgpt.com/docs/sandboxing) describes platform-native confinement and inherited limits for spawned commands, including Seatbelt on macOS. The [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) explicitly describes writable roots as **additional** roots, not a workspace subtraction mechanism. This supports the #4665 interpretation; it is not a live exact-file canary. [Docker's bind-mount documentation](https://docs.docker.com/engine/storage/bind-mounts/) provides read-only mounts and notes recursive-submount caveats. Inference: containers need an explicit source-write policy too. Local system manuals inspected read-only (`man 2 chmod`, `man 2 rename`, `man sandbox-exec`) establish owner mode changes, replacement semantics, and the deprecated launcher; no chmod/sandbox experiment was run because this preparation may create no probe files.

### Profiles — supported dimensions, not additional forks

Profile names below are proposed operational labels, not new standard vocabulary. The wrapper selects them; a job cannot claim a wider role in its prompt. All grants record role, backend/provider version, source paths, allowed operations, scratch roots, policy revision and expiry. A child receives an equal or narrower grant. Authority is separate from execution mechanism.

### Source scope, Git control state, scratch and external authority

- **Git:** proposed scoped workers read the real gitdir but cannot alter `we:.git/config`, `we:.git/hooks/`, refs, index, verification attestations, or `we:.githooks/`. Resolve worktree gitdir/common-dir indirection; never recursively grant a shared common-dir because a worktree needs a log. Keep policy, operation definitions and evidence outside worker-writable control. A job legitimately editing hook source produces a candidate patch in its granted lane; the privileged wrapper must not execute that candidate as its own trusted hook.
- **Verification:** #4665 currently grants the whole real gitdir for practical verification/logging. The target profile must replace that with wrapper-owned logs and a trusted verifier writing the marker and its temporary sibling. Simply removing the grant regresses #4665; simply retaining it makes “protected Git state” false. The agent may request verification, but cannot mint green evidence. Trusted code computes results against the actual source tree; agent-written test code runs with no greater rights than the worker, not with the wrapper's credentials.
- **Scratch:** provide per-run temp, fixture Git repos, test reports, coverage, browser artifacts and build outputs as explicit non-source capabilities. Inventory actual writes before enabling a profile. A source test/snapshot change still needs source scope; an ignored directory is not automatically safe scratch. Symlink/rename from scratch into source stays subject to the source policy. Shared admission locks belong to a broker/trusted test operation; never expose the whole lane pool. Isolate or mediate package/provider caches and declared localhost test ports.
- **Reads/network:** broad reads mean authorized repo/reference inspection, not a promise of secret protection or unlimited host access. Network enablement in #4665 is not HTTP-method restriction. Confinement alone cannot stop credentialed publish/merge calls: the typed-operation authority and credential boundary remain necessary. Preserve the free-read principle, distinguish a command that inspects from a test that executes worker-editable code.
- **Lifecycle:** before lease reuse, terminate descendants, revoke grant revisions, remove mounts/ACLs and verify baseline permissions. Preserve quarantined evidence if cleanup fails. No worker may retain an old grant after a widening rollback or lane reassignment.
