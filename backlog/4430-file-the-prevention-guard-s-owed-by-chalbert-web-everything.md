## Design

1. **Bound the tick's synchronous subprocesses.** Add an import-aware scanner in planned we:scripts/lib/daemon-sync-timeout-scan.mjs and wire it into we:scripts/check-standards.mjs. Initially enroll we:skills-src/conveyor/build-dispatch-daemon.mjs, including its injected `exec = execFileSync` seams. Require an explicit, finite, positive timeout on every synchronous child-process call in that module, including options passed via local bindings. Detect both `execFileSync` and `spawnSync`, aliases, and the injected exec seams; comments and string literals are not calls. Report unknown/dynamic options as unproven rather than silently accepting them. Add bounds to `cliPlanTick` and `cliDispatch`; retain the existing retry bound and prepare-status bound. Keep bounds named and injectable so tests exercise short deadlines without waiting for production durations. Use the existing daemon interval as the ceiling for the newly bounded per-call waits; this guarantees bounded calls, not a total tick deadline or grandchild cancellation.
2. **Redact before emitting diagnostics.** In the retry error path of we:skills-src/conveyor/build-dispatch-daemon.mjs, remove explicit GH_TOKEN/GITHUB_TOKEN values and GitHub token-shaped strings before whitespace normalization and the existing 400-character limit. Follow the existing token treatment in we:scripts/lib/gh-app-shim.mjs; do not claim arbitrary stderr is secret-free. Retain `timedOut` and useful nonsecret diagnostic text.
3. **Carry the reason, not a prose match.** In we:scripts/operations/open-pr-io.mjs attach the runner's structured reason as `reasonCode` on the thrown error. In we:scripts/operations/effect-executor.mjs preserve an optional string `reasonCode` on the failed/pending effect alongside the existing human-readable error. Preserve halt/replay semantics and clear a previous reason code when an attempt is retried or succeeds. In we:scripts/operations/deliver-item-wrapper.mjs classify only the submit effect's exact `reasonCode === 'blocked-on-infra'`. Missing, unknown, or malformed codes are nonretryable; quoted error text and top-level prose never supply authority. This path consumes a fresh CLI response, so it does not need a legacy prose fallback. Do not change the existing reason vocabulary.
4. **Keep primary checkout selection single-sourced.** Planned we:scripts/lib/primary-checkout.mjs exports a pure injectable resolver preserving trimmed `WE_PRIMARY_CHECKOUT` followed by the current home-relative default. Have `primaryInfraStoreEnv` consume it. Preserve the early explicit-file override, even for a nonexistent file, and keep the existence check on the inferred store only. This extraction does not change coordination roots or impose the primary checkout on unrelated checkout-relative operations.
5. **Exercise the real CLI on the existing CI route.** Extend we:scripts/conveyor/soak/define-break-test.mjs so each registered scenario test also runs the real we:scripts/conveyor/soak/run.mjs `break` command with a bounded subprocess. A fixed scenario must exit 0 with GREEN; a known unfixed scenario must exit 1 with RED. Exit 2, a signal, timeout, missing marker, or uncaught exception always fails an ordinary assertion outside the expected-failure wrapper. Existing scenario discovery and sharding already run these tests on daemon PRs, covering all changed/new registered breaks without a new workflow. Use the isolated soak environment and fake services, never operator sessions. Account for the additional scenario run within the existing soak test budget.
