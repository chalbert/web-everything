# Review a PR only once its required checks are green: fix the tests first, then review

Operator rule, 2026-10-01: "test should be first fixed then the review". Every automated PR review dispatch, including a ready PR re-armed after repair, must wait for every required check to succeed on its current head. Pending checks wait; genuine CI failures go through the existing repair path before review.

Incident supplied by the operator: PR #3432 reportedly had round 2 accepted at 9:42 PM ET while CI was red, then round 3 started at 10:05 PM before daemon-soak failed at 10:07 PM. These timestamps are incident context, not independently verified evidence in this preparation. The code evidence below establishes the dispatch gap without relying on that chronology.

## Design

1. Add a shared pure review-CI prerequisite in proposed we:scripts/lib/review-ci-gate.mjs. Inputs: current head SHA, required names, and checks for that SHA. Collapse reruns using the existing latest-per-name helper (we:scripts/lib/rollup-collapse.mjs:66-79,95-98). Admit only a nonempty known required set with a latest `completed/success` run for **every** required name. Missing, pending, failing, skipped, neutral, malformed, or unreadable required results refuse with the affected names and reason. Ignore checks outside the required set. A missing head or unknown required set never grants review.
2. Apply that prerequisite immediately before emitting any `kind: review` row from the common planner helper. Pass the existing required-set input through to it. Preserve draft, liveness, fix-claim, independence, already-reviewed-head, cap, and advisory-conversion semantics; this is an additional prerequisite for starting a review. Preserve folded refusal rows for the two parallel callers (we:scripts/conveyor/reconcile-core.mjs:1062-1068,1740-1745,1827-1832). Neither caller may override a non-green required check with a comment or label.
3. Add proposed we:scripts/lib/review-ci-gate-io.mjs for a fresh, repo-explicit preflight shared by the job and session dispatchers. Read the PR's live head, fetch the required names for that repo, read check runs by that SHA, then re-read the head; refuse if it changed. The current per-SHA reader provides the IO precedent (we:scripts/operations/pr-status-io.mjs:118-150). Run preflight before spawning either mode; the general staleness checks at we:scripts/operations/review-dispatch.mjs:561-566 and we:scripts/operations/review-job.mjs:525-527 concern the dispatch checkout, not PR CI. Return a structured `skipped` result on refusal, including head and reason, so no session, job record, or round tag is created. A later tick retries normally. This proves eligibility at the read boundary; it cannot make a subsequent GitHub head push atomic with local process creation.
4. Obtain required names through the existing repo-scoped reader, whose provenance is exposed as `live/cache/stale-cache/fallback` (we:scripts/lib/required-status-checks.mjs:90-131). At final dispatch, request a fresh read and refuse when the reader could only supply stale cache or fallback; unavailable evidence cannot authorize an all-required claim. Tests inject the reader, never call GitHub. Do not hardcode WE's three fallback names for other repos (the fallback is at we:scripts/lib/required-status-checks.mjs:45).
5. Keep CI repair ownership intact: own-code red still takes the existing heal/cap branch (we:scripts/conveyor/reconcile-core.mjs:1837-1866); failures attributed to main retain their rerun refusal instead of inventing a CI-heal (we:scripts/conveyor/reconcile-core.mjs:1716-1717). Both wait before review. An advisory `review-gate` failure does not block when absent from the required set; required-name inclusion already overrides advisory exclusions (we:scripts/operations/pr-status.mjs:125,171-175). If a repo actually requires a check that depends on review completion, refuse and expose that configuration conflict rather than silently exempting a required check or re-healing indefinitely.
6. Keep repair PRs ready. The ratified rule only permits draft for scope change or withdrawal: we:docs/agent/platform-decisions.md:5771-5809, anchor `fix-claim-draft-only-on-withdrawal`. Enforce this card with dispatch eligibility, not by converting every repaired PR to draft. No merge-gate or review-policy changes.
